# Z Chat — iOS shell (Capacitor)

Native iOS wrapper for **https://z-chat.men**, built with
[Capacitor](https://capacitorjs.com). The app loads the live site in a
WebView (`server.url` in `capacitor.config.ts`), so **the app auto-updates**:
every web deploy changes what users see immediately, with no App Store
release. Only the native shell (plugins, permissions, splash/icon, store
metadata) needs a new binary and review.

> **Reality check.** Building a signed, installable `.ipa` requires macOS +
> Xcode and an Apple Developer Program membership (99 USD/year). There is no
> way to produce a signed `.ipa` on Windows. This folder is the complete,
> production-ready skeleton; the `ios/` platform folder is generated by
> `npx cap add ios` on a Mac (or by the GitHub Actions workflow in
> `.github/workflows/ios-ipa.yml`, which runs on a macOS runner).

## Layout

| Path | Purpose |
| ---- | ------- |
| `capacitor.config.ts` | appId `men.zchat.app`, appName `Z Chat`, `server.url = https://z-chat.men` |
| `www/index.html` | placeholder web assets for `cap sync` (never shown in the app) |
| `package.json` | `@capacitor/core`, `@capacitor/ios`, `@capacitor/cli` |
| `tools/make-pwa-icons.ps1` | regenerates the PWA icons in the z-chat-app repo from `z-512.png` |

`ios/`, `android/`, `node_modules/` and build output are git-ignored — the
native folder is a generated artifact, not source.

## Build on a Mac

Prerequisites: macOS, Xcode (latest stable, command line tools selected),
Node 22+. Capacitor 8's iOS template uses **Swift Package Manager** by
default, so CocoaPods is only needed if you later add a plugin that still
ships a Podspec (`sudo gem install cocoapods`).

```bash
cd z-services/mobile
npm install

# Generate the native Xcode project (first time only)
npx cap add ios

# Copy config/web assets into the native project (SPM: no pod install needed)
npx cap sync ios

# Open the workspace in Xcode
npx cap open ios
```

In Xcode:

1. Select the **App** target → **Signing & Capabilities**.
2. Team: your Apple Developer team. Bundle identifier must stay
   `men.zchat.app` (create the App ID in the developer portal if needed).
3. Set the version/build number.
4. For a device build: pick your device/`Any iOS Device (arm64)` →
   **Product → Archive** → **Distribute App** → App Store Connect →
   Upload (or export an `.ipa` with the Development/Ad Hoc method for local
   testing).

## TestFlight (auto-updating distribution)

1. Upload the App Store `.ipa` to App Store Connect (Xcode Organizer or the
   CI workflow below).
2. TestFlight → add the build to a group → testers install it on iPhone.
3. Because the shell loads `z-chat.men`, **every web deploy updates what
   testers see immediately** — you only upload a new build when the native
   shell changes.
4. For a public release, submit the build for App Review once; subsequent
   web updates then flow through without review.

## CI: GitHub Actions → .ipa

`.github/workflows/ios-ipa.yml` (in the repo root) runs on a macOS runner and:

- `npm ci` → `npx cap add ios` (if missing) → `npx cap sync ios` (Capacitor 8
  Swift Package Manager project - no CocoaPods step needed)
- **No secrets set:** builds unsigned (`CODE_SIGNING_ALLOWED=NO`), packages
  `Payload/App.app` into `ZChat-unsigned.ipa` and uploads it as an artifact.
  Note: an unsigned `.ipa` **cannot be installed on a device** as-is; it is a
  build proof and can be re-signed later with a tool such as
  [Sideloadly](https://sideloadly.io) / `codesign`.
- **Secrets set:** imports the distribution certificate + provisioning
  profile, archives, and exports a signed App Store `.ipa` ready for
  TestFlight. The artifact is uploaded either way.

Trigger it from **Actions → iOS IPA (Capacitor) → Run workflow** (it also runs
on pushes that touch `mobile/**`).

### Secrets for a signed build

| Secret | What it is |
| ------ | ---------- |
| `APPLE_CERTIFICATE_BASE64` | Apple Distribution `.p12`, base64: `base64 -i dist.p12 \| pbcopy` |
| `APPLE_CERTIFICATE_PASSWORD` | password chosen when exporting the `.p12` |
| `APPLE_PROVISIONING_PROFILE_BASE64` | App Store `.mobileprovision` for `men.zchat.app`, base64 |
| `APPLE_TEAM_ID` | 10-character team ID (developer.apple.com → Membership) |
| `KEYCHAIN_PASSWORD` | any throwaway password for the CI keychain |

Optional, to upload to TestFlight automatically:

| Secret | What it is |
| ------ | ---------- |
| `APPLE_API_KEY_ID` | App Store Connect API key ID |
| `APPLE_API_ISSUER_ID` | App Store Connect API issuer ID |
| `APPLE_API_KEY_BASE64` | the `.p8` private key, base64 |

The upload step uses `xcodebuild -exportArchive` with `destination: upload`
and the API key, so no interactive Apple ID is needed. If the API key secrets
are absent the step is skipped and the `.ipa` is still available as an
artifact.

### Getting a certificate + profile without a Mac

1. Enroll in the Apple Developer Program.
2. On the portal, create the App ID `men.zchat.app`.
3. Create an **Apple Distribution** certificate — you need a CSR, which can
   be generated with OpenSSL on any OS.
4. Create an **App Store** provisioning profile for that App ID, download the
   `.mobileprovision`.
5. Export the certificate as `.p12` (Keychain on a Mac, or convert on
   Windows/Linux with OpenSSL), then base64 both files into the secrets above.

## App Store review caveats (honest)

- Apple guideline **4.2 (minimum functionality)** dislikes thin website
  wrappers. A remote-URL shell risks rejection. To strengthen the app, add
  native value such as push notifications
  (`@capacitor/push-notifications`) and offline/branded splash screens.
- Guideline **4.7** allows web content in apps, but remote code execution
  needs care: the shell loads your own site over HTTPS only (`cleartext:
  false`), and no third-party code is injected.
- Provide App Review with a working demo account, since the app starts at the
  sign-in screen.

## Zero-cost alternative: PWA

The z-chat-app repo ships a PWA (`public/manifest.webmanifest`, 192/512 +
apple-touch icons). On an iPhone today: open **https://z-chat.men in Safari →
Share → Add to Home Screen**. It launches standalone, is auto-updating by
definition, and needs no Apple account at all. The Capacitor shell exists for
the cases a PWA cannot cover (App Store presence, native push, etc.).
